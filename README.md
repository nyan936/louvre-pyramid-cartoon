# 卢浮宫玻璃金字塔 · 卡通三维场景

贝聿铭（I.M. Pei）最经典的代表作 —— 巴黎卢浮宫拿破仑庭院（Cour Napoléon）的玻璃金字塔，
做成 3D 精致的卡通风网页场景：**单文件 HTML，双击即开，零外部请求，打开就在动，还能调**。

交付物：`dist/louvre.html`（约 636 KB，内联 three r180 + addons）

## 打开方式

直接双击 `dist/louvre.html`（或在浏览器地址栏输入 `file://.../dist/louvre.html`）。
不需要服务器、不需要联网、没有任何外部资源请求。

## 场景内容（按实景资料还原的关键数据）

- **主金字塔**：高 21.64 m、底边 34 m、斜面与底座夹角 51.5°；幕墙按 13 等分菱形网格
  程序化生成（菱形 + 边缘三角，与实景 603 块菱形 + 70 块三角玻璃同构）；
  夜间模拟真实的内透光（塔内暖光点光源 + 玻璃自发光）。
- **三座小金字塔**：分别位于北（黎塞留）、南（德农）、东（叙利）三翼入口方向。
- **三块环绕水池**：外缘 45° 收角，绕金字塔北/东/南三面，西侧留出广场入口 ——
  与实景"方形水池转 45°、西侧三角形取消作为入口"的布局一致；
  水面用**单个 Reflector**（自定义水着色器：菲涅尔 + 水体本色下限 + 涟漪扰动 + 日月碎光），
  三块水面共用一次额外渲染，另有喷泉水珠与扩散涟漪。
- **宫殿三翼**：黎塞留（北）152 m、德农（南）152 m、叙利（东）136 m，
  底层拱窗 + 上层两排方窗 + 壁柱 + 层线 + 檐口，孟莎板岩屋顶、老虎窗、成排陶土烟囱帽；
  西端两座亭阁夹住通往杜乐丽花园的开口，中段亭阁带穹顶与牛眼圆窗，东侧钟阁带钟面；
  夜间按 34% 概率点亮暖色窗（`InstancedMesh` + `instanceColor`）。
- **细部**：路易十四骑马像（位于金字塔视觉中轴线起点，与实景一致）、
  卡鲁塞勒凯旋门（三拱 + 四马战车）、法式路灯（夜间地面光斑）、长椅、垃圾桶、
  条纹售货亭、修剪树篱花坛、树列、三色旗（顶点波动）、鸽子群、20 位卡通游客
  （往返 / 绕行 / 排队 / 拍照 / 坐姿五种行为）、卡通云、飞鸟群、星空与月亮、
  远景巴黎屋顶线 + 树带 + 埃菲尔铁塔（夜间整点亮灯）。
- **光照**：太阳（随仰角调制强度、色温、阴影强度）+ 半球天光 + 环境光 + 相机侧补光 +
  月光；昼夜状态由 `dayState(hour)` 统一驱动（含曝光曲线与雾色 = 地平线色 × 0.6）。
- **后处理**：Bloom（半分辨率）→ OutputPass（ACES + sRGB）→ 自写调色
  （饱和 / 对比 / 暖调 / 抬黑位 / 暗角 / 颗粒）。

## 构建

```bash
bash tools/build.sh src/main.js dist/louvre.html
```

`tools/build.sh` 用 esbuild 把 `three` 与 `three/addons` 打成 **IIFE**（ES module 在 `file://` 下会被
CORS 挡死），再把 bundle 内联进 `src/shell.html` 的 `/*__BUNDLE__*/` 占位符，并转义 `</script`。
默认 three 路径 `/home/nyan/.hermes/hermes-agent/node_modules/three`，可用 `THREE_DIR` / `ESBUILD` 覆盖。

## 自检 API（挂在 `window.__SCENE__`）

调试与自动审查用，页面自带，不需要额外工具：

```js
__SCENE__.setHour(17.75)         // 切时刻（立即生效，含光照/雾/曝光/材质更新）
__SCENE__.setCam('aerial')       // 切机位
__SCENE__.state.autoOrbit = false// 截图/采样前必须关掉自动环绕
__SCENE__.stats()                // fps / 三角形总数 / mesh 数 / GPU
__SCENE__.sample()               // 全屏均值、近黑占比、过曝占比、3×3 分块均值
__SCENE__.regionMean(0.34,0.6,0.4,0.66)  // 归一化矩形定点采样
__SCENE__.applyDay(dayState)      // 立刻按给定时刻状态刷新场景（setHour 内部已调用）
window.__ERRORS__                 // 运行期错误（正常应为 []）
window.__DBG__                    // { Raycaster, Vector2, Vector3 }：可在页面里射线拾取定位构件
```

### 两轮独立子代理审查发现并修掉的真实缺陷

均为"渲染后看图/采样"发现，不是猜的（第一轮审查：chrome-devtools MCP 打开页面，
自己渲染 8 张截图 + `read_image` 亲眼看 + 给 `regionMean` 数字）：

1. 远景地面盘（y=-0.18）盖在水面（y=-0.45）之上 → 三块水池洞口被堵死，水池完全不可见；下沉到 -1.60。
2. 南侧水池四边形绕序朝下被背面剔除 → 水面材质改 `DoubleSide`。
3. 宫殿窗户玻璃放在墙面**之后**（墙是 z∈[-26,0] 实心盒）→ 整排窗被墙吞掉；改做在墙面之前并加暗龛。
4. 亭阁开窗几何被 push 在 `mergeGeos(loc)` **之后** → 完全没生效。
5. 亭阁暗龛盒比玻璃厚 0.19 m → 把玻璃整块盖住，窗读成深色板；改成薄暗龛 + 前凸玻璃。
6. `Shape.holes` 传了点数组而非 `Path` → `this.holes[n].getPoints is not a function`，直接白屏。
7. 铜马骑像 y 从 0 起算 → 整座像被埋进 5.37 m 高的基座里。
8. `controls.maxPolarAngle` 把中轴机位从 y=4.6 顶到 y=17。
9. 卡通小人的正面是 +z，但朝向按 ±x 给 → 20 个人全部侧身走路。
10. 远处城市屋顶、埃菲尔铁塔塔腿、鸽子尾巴：几何先 translate 到位再 `rotate`（绕世界原点旋转）
    → 构件被甩到几百米外；统一改成 `atG()`（先绕自身原点转、再平移到位置）。
11. 云共用一份材质却被逐个设色，且交给光照 → 读作灰色石块；改为不受光的 `MeshBasicMaterial` + 顶点色。
12. 夜间金字塔内透光过曝成白团、月亮过大过亮、星星是大光斑 → 逐项下调并加月海贴图。
13. 立面窗在背光面是纯黑洞 → 加竖向天光渐变贴图 + 石框 + 十字分格棂 + 微弱自发光。
14. 远景城市是纯白无窗盒子 → 墙面加程序化窗格贴图（墙面与屋顶拆成两个 mesh）。
15. 阴影视锥过小 → 铺装出现直线状明暗硬接缝；从 ±132 扩到 ±172、far 620→900。
16. `roofParts` 声明插错函数（锚点撞缩进）→ 运行期 `ReferenceError`。

### 第三轮：用户实机发现的"边界一圈闪烁"（z-fighting）

用户在浏览器里拖动视角时发现金字塔基座那圈石缘闪烁。根因：石缘 `rboxG(w, ch, d, x, ch/2 - 0.42, z)`
的**顶面正好落在 y=0.00**，与广场铺装平面（y=0.00）**完全共面**且两者法线都朝上 → 抢深度。
取证用垂直射线打同一列：修复前第 1/第 2 个命中面分别是 `plaza`(y=0.0000) 与石缘(y=0.0000)，间距 **0.0 mm**；
修复后为石缘(y=0.0600) 与 `plaza`(y=0.0000)，间距 **60 mm**。
修法：石缘顶面抬到 +0.06；小金字塔台座底面沉到 -0.02；草坪 0.03→0.07；池壁顶 0.02→0.07；树篱底面下沉 0.04；
并给铺装材质加 `polygonOffset`（Factor/Units = 1）作为兜底。
复查：全庭院 **390 个网格点垂直扫描，不同网格上下间距 <5 mm 的共面对 = 0**。
两条断言已固化进 `tools/check-scene.sh`（[11][12]）。

### 第四轮：用户发现"鸟瞰下屋顶消失"

用户鸟瞰时看到三翼的**孟莎屋顶变成一大块浅灰平板**（只剩檐口一圈深蓝），像是屋顶没了。
活体 A/B（关掉屋面环境反射重采样）证明**不是光照打爆** —— 颜色几乎不变，问题在几何：
原来屋顶只有**一层棱台**，平顶进深 22 m（占进深 27 m 的 81%），等于"平顶盖 + 薄坡"，俯视当然是一块板。
改成**真正的两段坡**：陡下坡 ≈41°（檐口 → 断檐线）+ 缓上坡 ≈18°（断檐线 → 脊面）+ 顶部脊面 11.6 m，
并加断檐压条与脊线；屋面材质 roughness 0.64→0.74、envMapIntensity 1.05→0.70（正午俯视不再泛白）。
复测三个时刻的屋面像素：正午坡面 [102,127,151]（板岩蓝）、15:24 [96,122,149]、
黄金时刻 [68,53,53]～[141,92,58]（暖调、无死黑）。
新增断言 [13]（顶面进深必须 ≤12 m）。

### 自检 API 的两个坑（本轮实测并修掉）

- **`setCam()` 有 1.25s 缓动**：切完立刻采样/截图会读到中间态（审查员上轮也被它影响）。已新增 `__SCENE__.jumpCam(name)` 瞬时切机位。
- **换环境贴图后第一帧不可信**：`refreshEnv` 会重建 PMREM 环境贴图，材质重编译要过几帧；原来立刻 `dispose()` 旧贴图会让第一帧发黑。
  已改为延迟一轮释放，并让 `sample()` / `regionMean()` 先排空 6 帧、直接 `gl.readPixels` 读后备缓冲（不再经 2D 画布中转）。
  改状态后仍建议等 1 秒再取证。
